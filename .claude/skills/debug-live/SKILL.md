# Разбор на живой игре

## Состояние на момент падения

- `scripts/stage.sh` при падении останавливает экземпляр — сервер сохраняет игру в
  `run/iN/server/saves/bot.zip`. Поднять тот же экземпляр без новой карты:
  `INST=N NEW_MAP=0 timeout 300 scripts/newmap.sh`.
- Начальное состояние стадии — снимок `<сид>-(N-1)` на свободном экземпляре (обычно 4):
  `INST=4 timeout 600 scripts/snapshot.sh load <сид>-<N-1>`, потом
  `INST=4 bash -c 'source scripts/inst.sh; timeout 600 bin/bot -t 8m stage N'` — без
  сохранения снимка.
- После — `INST=N scripts/stop.sh`. Не оставлять висящих окон.

## Смотреть — только чтение

- `INST=N bash -c 'source scripts/inst.sh; scripts/rcon.py "/sc …rcon.print(…)"'` — статусы
  машин (`defines.entity_status`), содержимое сундуков и лент (`get_transport_line`), топливо,
  исследования. Никаких команд, меняющих игру.
- `bin/bot player`, `bin/bot insert …` и т.п. — действия руками бота (это ввод, честно).
- Раскладки стадий — `run/iN/state-stage*.json`, план — `state-stage5.json`.

## Схема раскладки

Нарисовать ASCII вокруг места ошибки: первая буква постройки, `R` — резерв, `#` — нельзя
строить, `P` — порт/цель (python по state-файлу или временный дамп из Go). Так нашлись: лента,
прошедшая через вход кластера; резерв, закрывший порт.

## Временная отладка

- Отладочный вывод в коде (`DBG …`, дамп в `$CLAUDE_JOB_DIR/tmp/`) — только на время разбора.
- Имя дампа — уникальное на попытку (координаты в имени): иначе следующая попытка перепишет
  первую, и разбор пойдёт не по той.
- После — `git checkout` файла или убрать правкой; в коммит отладка не попадает.
