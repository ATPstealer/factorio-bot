# Золотой прогон

**Главная задача — сделать код лучше**: понятнее, короче, без лишнего, устойчивее. Шаги 0–4 —
это и есть работа; прогон (шаг 5) — проверка её качества: на 3 новых сидах дойти до последней
стадии (`stages.md`) с минимумом правок по ходу (**лимит — 10 правок кода бота** на все стадии и
карты вместе). Каждая правка в прогоне — сигнал, что шаги 0–4 что-то упустили: после прогона —
вывод, что улучшить в коде, а не только заплатка.

## 0. Документы — сначала (с пользователем)

Работа начинается с документов, а не с кода: код делается по документам (`docs-first`).
- Прочитать `CLAUDE.md`, `README.md`, `stages.md`, `cluster.md`, `zones.md`, `capabilities.md`,
  скилы — найти несоответствия: документ с документом (одно правило описано по-разному,
  противоречия, устаревшие номера стадий и имена), документ с кодом (описано, но не сделано;
  сделано, но не описано; описано не так, как работает).
- Показать пользователю списком, по каждому — решение вместе: какой вариант верный. Поправить
  документы; где верен документ — код приводится к нему на шагах 1–4.

## 1. Рефакторинг (до прогона)

- Полный проход по коду: дубли — в общие функции, длинные функции — на понятные части,
  имена — по смыслу, комментарии — правдивые (устаревшие поправить или убрать).
- Мёртвый код: `~/go/bin/deadcode -test -tags e2e ./...` — удалить; неиспользуемые
  параметры, константы, файлы состояния, скрипты.
- Код — к документам, согласованным на шаге 0 (что решили «верен документ» — сделать).
- После каждого шага — `go vet`, юнит-тесты, коммит. В конце — весь бенч `PAR=4
  scripts/bench.sh` (стадии не идут!): зелёный, как до рефакторинга (новые падения — чинить).

## 2. Удаление лишнего

- Устаревшие стадии, ветки кода под старые решения, отладочные куски, старые снимки и файлы
  в `run/`, которые больше не нужны (спросить, если не уверен).

## 3. Заметки — с пользователем

- Собрать всё отложенное: `questions.md` (открытые и отложенные), «Находки» в
  `stages-report.md`, `TODO`/`FIXME`/«пока не в коде»/«потом» в коде и документах,
  «Что добавить на карты» в `test/e2e/README.md`.
- Показать пользователю списком, по каждой — решение вместе: сделать / отложить / убрать.
  Сделанное — по обычным правилам (`docs-first`, `bug-to-test`).

## 4. Укрепление — со всех сторон

Цель — бот не падает от того, что можно предвидеть:
- каждый сбой из прошлых прогонов (`stages-report.md`) — e2e-тест есть и зелёный на картах `-0` (`MAPS=all`);
- проверки перед стадией (`preflight`): всё, что можно узнать «на бумаге», — до первого
  действия;
- повторы и запасной путь там, где ввод ненадёжен (клик не дошёл, окно не открылось, путь
  закрыт); таймауты на всё; понятные ошибки;
- инвентарь, хранение, топливо, ленты, ходьба — проверить слабые места по логам прошлых
  прогонов (`run/stages/*.log`: «застрял», «повторяю», «не дошёл», «полон»);
- весь бенч зелёный (кроме известного и записанного).

## 5. Прогон — самостоятельно

С запуска стадий работа самостоятельная — скил `autonomous-work` (и `stage-runs`).
- 3 новых случайных сида (`SEED=$(( (RANDOM << 15 | RANDOM) % 4000000000 ))`), записать их в
  отчёт. Карты — независимо, по экземпляру на карту: `INST=k scripts/stage.sh 1-<последняя>
  <сид>` (k = 1, 2, 3).
- Упала стадия — разбор как обычно (`bug-to-test`, `debug-live`); **каждая правка кода бота
  считается** (коммит с пометкой `golden-run: правка N/10`). Правка одна на несколько карт —
  одна. Правки документов и скриптов прогона без изменения поведения бота — не считаются.
- Лимит 10 исчерпан — прогон остановить: отчёт (шаг 6: что дальше мешает, вопросы), потом
  доработки по выводам отчёта (шаги 1–4 по нужным местам) и **новый прогон на других 3 новых
  картах** (новые сиды, счёт правок — с нуля). Так — пока прогон не пройдёт все стадии не больше
  чем с 10 правками (правило пользователя).
- Снимки — `<сид>-N` как обычно.

## 6. Отчёт

- `stages-report.md` — раздел «Золотой прогон <дата>»: сиды, таблица стадия × карта (мин,
  ✓/✗), число правок и каждая правка (стадия, карта, причина, тест), находки.
- `questions.md` — решения без «ок» и открытые вопросы.
- В чат — короткая сводка со ссылками на файлы.
