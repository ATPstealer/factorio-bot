# Прогон стадий

## Правила скорости (пользователь 27.10: «за последние дни мало продвинулись»)

- **Цель прогона — дойти до стадии 41.** Цель дня — «стадия N на трёх картах». Рефакторинги и
  улучшения, без которых стадия проходит, — в `questions.md` («Дела на будущее»), не сейчас.
- **Пока идёт прогон — код плана (стадии 2–5, `internal/cluster`) не трогать**: правка плана
  обнуляет снимки после стадии 2 (до стадии 15 — 4–5 ч игры). Правки планов копить и вносить
  пачкой между прогонами: документ → прогон без игры на всех картах (`exp.sh`, `TO=5`) → один
  прогон в игре. Во время прогона чинить только механику упавшей стадии.
- **Две дорожки карт**: вперёд по стадиям — 3 обычные карты; сложные (утёсы, вода, тесно) —
  только без игры, для планов (`run/worlds/*.gob`).
- **Починку — сначала на экземпляре 4**: снимок перед упавшей стадией, стадия с лимитом 5–15
  мин, проверить именно то место; потом перезапуск карт. Вслепую три карты не перезапускать.
- **Находка в игре, которую видно по плану**, — новая проверка на бумаге (`preflight`,
  `flowCheck`), чтобы больше не дожидаться её часами.
- **Где уходит время** — `scripts/stage_time.py` по журналам стадий (ходьба, крафт, стройка,
  сундуки, добыча): чинить самое долгое.
- **После стадии 41** (пользователь 27.10) — отдельный этап ускорения: по `stage_time.py`
  найти, что ест время, и улучшать прогоны по одной стадии (снимок перед стадией, экземпляр 4,
  замер до/после). Только улучшения кода, верные на любой карте; подгонка под карту запрещена
  (`CLAUDE.md`).

## Запуск

- Одной командой скрипта, не самодельными циклами:
  `scripts/stage.sh N-M 851731946 859088572 794457638` — стадия на всех картах параллельно (по
  окну на карту, экземпляры 1, 2, …), следующая — когда все закончили. Не выполнена хоть на
  одной — стоп.
- Карт параллельно — не больше 3 (экземпляры 1–3); экземпляр 4 — свободен для разбора
  (`debug-live`) и тестов (`bug-to-test`) (правило пользователя 27.10).
- Перед запуском — закрыть всё старое: `for i in 1 2 3 4; do INST=$i scripts/stop.sh; done`.
- В фоне (`run_in_background`), вывод — в `run/<что>.out`.
- Монитор итогов (30 мин, перезапускать по истечении):
  `tail -n0 -F run/stages/summary.txt | grep --line-buffered -E "выполнена|НЕ выполнена|нет снимка|не создалась|стоп|стадии"`.
- Лимит стадии — `LIMIT=мин` (по умолчанию 120, разведка — стадия 1 — 1080: до 25 квадратов по ~40 мин).

## Упала стадия

1. Дождаться, пока остальные карты закончат эту стадию (скрипт сам остановится).
2. Причина — по `run/stages/sN-<сид>.log` и снимку сбоя. Механика (не дошёл, не поставил…) —
   скилл `bug-to-test`; логика стадии или план — чинить сразу; нужна игра — `debug-live`.
3. Код плана поменялся (стадии 2–5, `internal/cluster`) — перегнать с той стадии, где план
   строится, и все следующие: старые снимки построены по старому плану.
4. Перезапуск с упавшей стадии на всех картах; если на остальных она уже прошла и код
   затронул только редкий случай — можно только упавшую карту (`scripts/stage.sh N СИД`), потом
   дальше на всех.

## Отчёт

- Итоги — таблица в `stages-report.md` (стадия × карта, минуты, ✓/✗) и «Находки»: только что
  нашлось и как починено, стадии не пересказывать.
- Вопросы и решения без «ок» — `questions.md`.
- В чат на каждое событие монитора — одна короткая строка.
- Пользователь сказал «стоп» — остановить ботов (`kill` по `pgrep -x bot`, не `pkill -f` с
  шаблоном — убьёт свой же bash) и игры, отчёт в файл, коммит.

## Ночной режим (пользователь ушёл)

Работать самому до конца стадий: чинить, перезапускать. Решения, которые обычно требуют «ок»,
— в `questions.md` отдельным списком. Утром — короткая сводка в чат со ссылками на файлы.
