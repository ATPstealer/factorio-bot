# Баг механики → тест сначала

## Порядок

1. **Разобрать ситуацию** по логу стадии (`run/stages/sN-<сид>.log`) и снимку сбоя
   (`run/debug/` или `run/iN/debug/`): что делал, где стоял, что вокруг, сколько чего в
   инвентаре. Если надо — поднять сохранение упавшей игры (скилл `debug-live`).
2. **Тест в `test/e2e/<группа>_test.go`** (env, interface, walk, hands, knowledge): одна
   способность — один тест, без перекрытий. В комментарии — откуда ситуация (стадия, карта,
   текст ошибки). Помощники — `helpers_test.go` (`handsT`, `have`, `freeArea`, `ctxT`…).
   Запросы — только чтение, действия — только ввод. Тест за собой не убирает.
3. **Бенч на 4 картах `-0`**: `PAR=4 scripts/bench.sh <Шаблон>` — параллельно, по экземпляру на
   карту. Подряд на одном экземпляре (`INST=4 SNAP=<сид>-0 SKIP_BUILD=1 scripts/test.sh
   <Шаблон>`) — только пока экземпляры 1–3 заняты стадиями; освободились — снова `PAR=4`.
4. **Чего на карте нет** для теста (лес, уголь, технологии, предметы) — строка в раздел «Что
   добавить на карты» в `test/e2e/README.md` и в чат; работа не ждёт.
5. **Починить код бота** (`internal/act`, …), прогнать тест снова на всех картах.
6. Коммит: «что чинил (где случилось); e2e TestX».

## Правила

- Тест, который упал, **не менять никогда** (только по прямой просьбе пользователя) —
  доделывать бота под сложную ситуацию.
- Не повторилось в тесте — честно сказать, всё равно сделать бота устойчивее (повторы,
  проверки) и записать догадку о причине как догадку.
- Любой запуск игры — с лимитом времени (`-t`, `timeout`).
