# Сначала документы

Пользователь хочет видеть, на основании чего бот работает. Код — по документу, не наоборот.

## Порядок

1. Найти документ, где живёт правило: `zones.md` (зоны базы), `cluster.md` (кластеры),
   `stages.md` (стадии и общее для всех стадий), `CLAUDE.md` (как устроен проект).
2. Правка — инструментом Edit (пользователь видит diff), коротко, в стиле документа.
3. Показать пользователю, что поменялось: цитата новых строк, без пересказа старого.
4. Если в формулировке есть неоднозначность — один конкретный вопрос с вариантами
   (например: «сдвиг считать от левого края или от середины?»).
5. Ждать «ок» / «делай». Только потом код.
6. Ответ пользователя — сразу в документ (и код), чтобы не было расхождений между чатом,
   документом и кодом; вопрос из `questions.md` — удалить (там только открытые, «решено» не
   писать).

## Нельзя

- Придумывать правила самому и молча вписывать их в документ или код («проход 3 вместо
  коридора 12» — пришлось откатывать).
- Начинать код до «ок», даже если кажется очевидным.
- Оставлять в документе то, что в коде не сделано: сделал меньше — поправь документ и скажи.

## Исключение

Пользователь ушёл и велел работать самому (ночной режим): правило, без которого не
продвинуться, можно ввести — но записать в документ и отдельным пунктом в `questions.md`
(«добавил сам, без ок: … Так ок?»), чтобы утром подтвердить или откатить.
