# E2E-тесты

Тесты на живой игре: бот действует только вводом (мышь, клавиатура), проверка — чтением состояния через мод. Требуют запущенной игры (`scripts/run.sh` или `scripts/newmap.sh`).

## Запуск

- Все: `scripts/test.sh` (~5 мин). Перед e2e всегда `go vet` и юнит-тесты.
- Один или несколько по имени (шаблон `-run`): `scripts/test.sh Walk`, `scripts/test.sh 'SetRecipe|SetFilter'`.
- Карта — текущая; игра перезапускается на ней же, только если не запущена или изменился мод (хеш `run/mod.hash`). `NEW_MAP=1` — новая случайная, `SEED=…` — конкретная (`SEED=927139741` — хорошая для быстрого начала), `SNAP=имя` — со снимка, `SAVE_AS=имя` — снимок после зелёного прогона.
- Снимки: `scripts/snapshot.sh save ИМЯ "описание"`, `load ИМЯ`, `list`.

## Бенч — все тесты на картах-эталонах

- `scripts/bench.sh` — по очереди на каждом снимке `run/snapshots/<сид>-0`: грузит снимок, гоняет все e2e (`scripts/test.sh`). `scripts/bench.sh Walk` — только тесты по шаблону.
- Результат: лог карты — `run/bench/<снимок>.log`, итог по картам — `run/bench/summary.txt` (прошло, упало, пропущено, какие упали), статистика — таблица ниже (в «Когда» — снимок).
- Снимки называются `<сид карты>-<номер>`: `-0` — карты для бенча; `-1`, `-2`, … — после стадий. В папке снимка: `bot.zip` (сейв сервера), `map.json` (сид, дата создания карты), `NOTE.txt` (описание, когда сохранён), `state*.json` (состояние бота, если было).
- Тесты меняют карту (ставят постройки, рубят, разведывают) — снимок `-0` при этом не меняется: каждый прогон начинается с него заново.
- Правка одной способности — её тест; перед коммитом — все.
- Каждый прогон дописывается в статистику (`test/e2e/stats.tsv`, таблица внизу) — `scripts/test_stats.py`.

## Тесты

Тесты разложены по файлам групп. Предметы для теста набирает `have` (`helpers_test.go`): сырьё (дерево, камень, уголь, руда) — руками, остальное — крафт; нужны пластины, а их нет — тест пропускается. Тесты не убирают за собой.

### Окружение — `env_test.go`

| Тест | Что проверяет |
|---|---|
| `Config` | файлы настроек без игры: генерация карты без кусак и с обычными утёсами; сервер без автопаузы и проверки пользователей; `config.ini` клиента — масштаб интерфейса, звук выключен; мод подключён симлинками у сервера и клиента |
| `Game` | игра запущена правильно: сервер работает; моды загружены, версия мода в игре = файлу; мод отвечает на `ping`; карта та (сид); клиент бота в игре, окно открыто в Xephyr |

### Интерфейс — `interface_test.go`

| Тест | Что проверяет |
|---|---|
| `Guards` | меню игры (Esc) и карту (Tab) бот закрывает сам перед действием |
| `InventoryWindow` | E открывает окно персонажа, Esc закрывает; меню игры не открывается |
| `PickFromInventory` | взять в руку предмет из инвентаря, которого нет на панели (поиск в окне инвентаря, привязка к панели); Q — рука пуста, в инвентаре столько же |
| `StartResearch` | запустить доступную технологию (предпосылки изучены) через окно технологий: поиск → «Start research»; она текущая или в очереди |
| `SetRecipe` | поставить сборщик, задать рецепт шестерён, сменить на медный провод (кнопка смены), поднять; рецепт сверяется с игрой |
| `SetFilter` | поставить инсертер, включить фильтр и задать «уголь»; фильтр сверяется с игрой |

### Ходьба — `walk_test.go`

| Тест | Что проверяет |
|---|---|
| `Walk` | дойти клавишами до точки и обратно с точностью 0.5 тайла |
| `PathAroundLake` | путь в обход ближайшего к игроку водоёма (не меньше 100 тайлов, открыт целиком) (точки по разные стороны, путь с поворотами) и дойти по нему |
| `Unstuck` | персонажа обступили кольцом из 8 сундуков, дальше одна команда «иди туда» за кольцо — как выйти, бот решает сам; проверка — дошёл |
| `Explore` | разведка: идти к краю открытой карты, пока не откроется ещё 10 чанков |

### Руки — `hands_test.go`

| Тест | Что проверяет |
|---|---|
| `Craft` | 2 дерева → деревянный сундук через окно крафта; прибавка и списание в инвентаре |
| `FurnaceScenario` | добыть камень → скрафтить печь → поставить → положить уголь и руду → забрать пластины |
| `PlaceNextToSelf` | сундук — на клетку, где стоит персонаж (отойти и поставить), печь 2×2 — вплотную |
| `PlaceAmongBelts` | в квадрате 12×12 ленты на случайной половине клеток со случайными направлениями; выйти из зоны; поставить печь 2×2 в середину (`SEED_BELTS=…` — повторить расстановку) |

### Знания — `knowledge_test.go`

| Тест | Что проверяет |
|---|---|
| `SnapshotMatchesGame` | снимок справочника в репозитории (на нём юнит-тесты калькулятора) совпадает с игрой |
| `AvailabilityMatchesForce` | доступные рецепты, посчитанные по изученным технологиям, совпадают с открытыми в игре |
| `RocketPartPlan` | калькулятор: ракетная часть 1/мин по живому справочнику и через CLI `bin/bot calc` |

## Что добавить на карты

Чего не хватает на картах `-0`, чтобы тесты не пропускались (добавляет пользователь, потом снимок пересохраняется). Чего нет по рельефу карты (лес, деревья нужного вида) — не добавляется: такой тест идёт там, где есть, на остальных пропускается.

24.10: на новые карты `1067809293-0` и `139321812-0` добавлены пластины, уголь и исследования.
28.10: карты `1028292478-0`, `859088572-0`, `260647970-0` — копии снимков после стадии 41 (база
до синей науки: нефть, цистерны, двигатели, сталь). Нужно ещё:
- `TestGatherFullInventory` — карта, где инвентарь полон и в нём есть сундук (деревянный или
  железный), уголь рядом;
- `TestCraftPump`, `TestFlushPipeline` — есть на картах после стадии 41 (если в инвентаре нет
  двигателя — бот не носит их с собой; тогда тест пропускается).
