# Factorio Bot — план

Цель: бот с нуля строит базу и запускает ракету (Factorio 2.0.77, base, без Space Age) без единого клика игрока.
Первая карта — фиксированный сид, кусаки выключены. Дальше — адаптация к любой карте.

---

## 0. Ключевые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Версия | Factorio 2.0.77, только `base` | ✅ утверждено. «Улететь» = запуск ракеты (победа в base). |
| Честность | ✅ **Действия — только ввод мыши/клавиатуры** в окно игрового клиента (эмуляция ввода ОС). Мод **ничего не меняет** в игре — только читает состояние. | Правила игры соблюдает сама игра (досягаемость, инвентарь, время крафта) — отдельная проверка правил не нужна. |
| Глаза | Lua-мод `botbridge` — **read-only** сенсоры, отдаёт JSON по RCON | Информация через мод разрешена. Скриншоты — только для калибровки/проверки GUI. |
| Руки | Go-бот шлёт ввод через **XTEST** (X11, сессия XFCE) в окно клиента | Реальные клики/клавиши, как у живого игрока. |
| Запуск игры | Headless-сервер (`--start-server`, RCON, свой `--config`/write-data) + **клиент** Steam, подключённый к нему | RCON есть только у сервера; клиент — тот, кем «играет» бот. |
| Изоляция ввода | Клиент запускается во вложенном X-дисплее (**Xephyr**), бот кликает только туда | Твоя мышь/клавиатура свободны; ты смотришь в окно Xephyr. |
| Строительство в поздней игре | Чертежи через GUI (импорт строки из буфера обмена) → призраки → строительные роботы | Как живой игрок. Цель — дойти до роботов как можно раньше. |

## 1. Архитектура

```
┌──── Factorio headless server ────┐        ┌──── Xephyr :1 ─────────────────────┐
│ mod "botbridge" (read-only)      │◄──────►│ Factorio client (игрок бота)       │
│  ├─ remote interface (запросы)   │  game  │   ▲ мышь/клавиатура (XTEST)         │
│  ├─ sensors (прототипы, карта,   │  net   └───┼────────────────────────────────┘
│  │   сущности, игрок, GUI-state) │            │
│  └─ event buffer                 │            │
└───────▲──────────────────────────┘            │
        │ RCON: remote.call("bot", ...) → json  │
┌───────┴────────────────────── bot (Go) ───────┴─────────────────────────────┐
│  rcon client → bridge API (только чтение)                                   │
│  input        (XTEST: мышь, клавиши, удержание, буфер обмена)               │
│  camera       (мир ↔ пиксели: позиция игрока, зум, разрешение, UI scale)    │
│  gui driver   (макросы: инвентарь, крафт, тех-дерево, окно сущности)        │
│  world model / knowledge / strategist / planner / layout                    │
│  executor     (примитив → ввод → проверка результата через сенсоры)         │
│  monitor / logs+replay                                                      │
└─────────────────────────────────────────────────────────────────────────────┘
```

Правило: в remote interface мода нет ни одного метода, меняющего игру. Бот по RCON вызывает только `remote.call("bot", ...)`, никаких произвольных `/c`.

Структура репо:
```
/mod/botbridge/          info.json, control.lua, sensors/*.lua
/cmd/bot/                main.go
/internal/rcon/          RCON-клиент
/internal/bridge/        API к моду (чтение)
/internal/input/         XTEST: мышь, клавиатура, буфер обмена
/internal/camera/        проекция мир ↔ экран
/internal/gui/           макросы работы с GUI игры
/internal/world/         модель мира
/internal/knowledge/     рецепты, техи, калькулятор
/internal/planner/       HTN, стек задач
/internal/layout/        шаблоны, размещение, A* для лент
/internal/executor/
/internal/monitor/
/scripts/                запуск сервера/Xephyr/клиента, генерация карты, установка мода
/blueprints/             шаблоны модулей (blueprint-string)
```

## 2. Стадии разработки

Каждая стадия — отдельный критерий готовности. Следующую не начинаем, пока не пройден критерий.
Критерий оформляется e2e-тестами `test/e2e/stageN_test.go`; `scripts/test.sh` гоняет все стадии — после каждой стадии проверяем, что предыдущие не сломаны.

### Стадия 0. Окружение
- Генерация карты: фиксированный сид, `map-gen-settings.json`: `enemy-base` frequency=0, утёсы выключены (`cliff_settings`).
- Headless-сервер: `--start-server bot.zip --rcon-port 27015 --rcon-password ... --server-settings ...` с `"auto_pause": false`, отдельный `--config` (свой write-data, иначе конфликт lock-файла с клиентом) и `--mod-directory`.
- Xephyr `:1` фиксированного разрешения (например 1920×1080), клиент Factorio запускается в нём, автоподключение `--mp-connect localhost`.
- Настройки клиента фиксированы: разрешение, UI scale 100%, оконный режим, раскладка клавиш по умолчанию (бот на неё опирается).
- Мод ставится в mods-dir сервера и клиента (симлинк).
- Пакеты: `xserver-xephyr`, `xdotool`/libXtst (для отладки), `xclip`.
- Go toolchain (сейчас `go` не в PATH).

**Готово, когда:** одна команда поднимает сервер + Xephyr + клиент, клиент в игре на карте без кусак.

### Стадия 1. Мост (глаза) и руки (ввод) — ✅ готово
- Мод: `remote.add_interface("bot", {call})`, ответ через `rcon.print(helpers.table_to_json(...))`. Только чтение.
- Go: RCON-клиент, `bridge.Call(method, args, &out)`. Пагинация не понадобилась: RCON отдаёт ≥2 МБ одним пакетом.
- Методы: `ping`, `tick`, `get_player` (позиция, зум, разрешение, инвентарь, quickbar, cursor, `opened`, крафт-очередь, reach, selected), `find_nearest`, `entity_at`.
- Event buffer: мод копит события, бот забирает `poll_events{after}`.
- Go-ввод через XTEST (xgb, без cgo) в `:1`: клавиши, текст, мышь, колесо. Буфер обмена — отложен до чертежей (стадия 9).
- Камера: проекция мир ↔ пиксели по позиции игрока и зуму. Зум не меняем (1.5 устраивает) — читаем из игры. Калибровка: наведение подтверждается `selected`.

**Готово, когда:** бот подходит клавишами WASD к точке, наводит курсор на дерево (`selected` подтверждает) и срубает его ПКМ.
Тесты: `test/e2e/stage1_test.go` (Walk ≤0.5 тайла, ChopTree + событие mined_entity).

### Стадия 2. Сенсоры (глаза)
- `dump_prototypes`: рецепты, предметы, сущности (размеры, скорость крафта, энергия, ящики-в/ых), технологии (стоимость, зависимости, что открывают). Кэшируется ботом в файл — один раз на версию игры.
- `scan_resources(area)`: ресурсные поля — тип, тайлы, количество. Бот кластеризует в «патчи».
- `scan_entities(area)`: сущности, их статус (`LuaEntity.status`: working / no_power / no_input / output_full ...), содержимое.
- `scan_tiles(area)`: вода, непроходимое, деревья/камни (препятствия).
- `get_force`: исследования, текущее исследование, прогресс.
- `get_production_stats`: статистика производства/потребления (для мониторинга).
- Подписки: on_built, on_entity_died, on_resource_depleted, on_research_finished, chunk_charted.

**Готово, когда:** бот строит в памяти карту стартовой зоны (ресурсы, вода, препятствия) и выводит её отладочной картинкой (PNG).

### Стадия 3. Примитивы действий через ввод
Каждое действие: `start → running → done | failed(reason)`. Ввод — от бота, результат проверяется сенсорами мода (позиция, инвентарь, сущности, `opened`).

| Действие | Ввод |
|---|---|
| `walk_to(pos)` | путь считает бот (A* по сетке из сенсоров); удержание WASD-комбинаций, коррекция по позиции; детект застревания |
| `mine(entity)` | навести курсор (камера) → удерживать ПКМ до исчезновения/изменения сущности |
| `craft(recipe, n)` | `E` → поиск рецепта (Ctrl+F, ввод имени) → клик (Shift/ПКМ для 5/все) → `Esc` |
| `place(item, pos, dir)` | взять в руку (слот quickbar или клик в инвентаре / `Q` пипетка) → `R` поворот → навести → ЛКМ |
| `insert/take(entity, item, n)` | Ctrl+ЛКМ/Ctrl+ПКМ по сущности (быстрый перенос) или открыть окно сущности и кликать слоты |
| `set_recipe(entity, recipe)` | открыть сущность ЛКМ → поиск рецепта → клик |
| `rotate`, `pickup` | `R` / удержание ПКМ на своей сущности |
| `research(tech)` | `T` → поиск → клик → `Esc` |
| `fuel` | взять уголь в руку → ЛКМ/Ctrl+клик по burner-сущности |
| `place_blueprint` | позже: импорт строки (буфер обмена → GUI библиотеки), выбор в руку, клик |

- **GUI driver**: макросы опираются на фиксированное разрешение и UI scale; координаты элементов калибруются один раз (скриншот + шаблон), подтверждение шагов — по `player.opened` / содержимому курсора / инвентарю из мода.
- Ошибки ввода (клик мимо, окно не открылось) → повтор с перекалибровкой.

**Готово, когда:** сценарий «добыть 10 камня → скрафтить печь → поставить на руду → закинуть уголь и руду → забрать пластины» проходит без ручного вмешательства, только вводом.

### Стадия 4. Знания и калькулятор
- Граф рецептов и технологий из дампа.
- Калькулятор: «N предметов/мин X» → сколько машин каждого типа, сколько сырья, сколько энергии, сколько лент.
- Путь по техам: что исследовать, чтобы открыть рецепт/здание; цена в науке.
- Выбор рецепта при альтернативах (нефть: basic → advanced → cracking).

**Готово, когда:** `bot calc rocket-part 1/min` выдаёт полное дерево производства и список нужных исследований.

### Стадия 5. Планировщик и стек действий
Иерархия:
1. **Стратегия** — фаза игры и производственные цели (например: «красная наука 30/мин», «железо 600/мин»).
2. **Цели** — разница «нужно − есть» → список целей: `HaveProduction(item, rate)`, `HaveItem(item, n)`, `Researched(tech)`, `HavePower(MW)`.
3. **HTN-декомпозиция** — цель раскладывается на задачи по методам:
   - `HaveItem(iron-plate, 50)` → есть в сундуках? забрать : есть производство? подождать/забрать : скрафтить/добыть руками.
   - `HaveProduction(iron-plate, R)` → найти патч → выбрать модуль → разместить → собрать материалы (рекурсия `HaveItem`) → построить → подключить энергию/вход/выход → проверить работу.
4. **Стек примитивов** — `walk_to, mine, craft, place, insert...` исполняет executor.

Перепланирование:
- Действие упало (нет предмета, место занято, путь не найден) → откат до ближайшей задачи, у которой есть альтернативный метод.
- Событие монитора (патч истощается, нет энергии, наука не идёт) → новая цель с приоритетом, вставляется наверх стека; текущая задача приостанавливается, если позволяет.
- Периодический пересчёт целей (раз в N секунд игрового времени).
- Приоритеты: аварийные (энергия, истощение питающего патча) > блокирующие текущую цель > развитие.

Состояние планировщика сохраняется на диск (для рестарта бота без потери контекста) и пишется человекочитаемый лог «почему я это делаю».

**Готово, когда:** цель «иметь 5 каменных печей на железе с углём» бот выполняет сам, начиная с пустого инвентаря, и восстанавливается, если ему вручную удалить печь.

### Стадия 6. Layout-движок (где и как строить)
- Сетка занятости карты (сущности, вода, руда, зарезервированные зоны).
- **Модули** — параметризуемые шаблоны: «шахты на патче», «линия печей», «блок сборщиков под рецепт», «паровая электростанция», «помпа + бойлеры», «нефтянка», «научный блок». Описаны как чертежи + метаданные (входы/выходы/энергия/размер).
- **Генерация шахт под форму патча** (не шаблон — раскладка дрелей по тайлам руды + ленты сбора).
- **Глобальная планировка**: main bus от плавильни; модули вдоль шины. Зоны резервируются заранее под будущее (по калькулятору).
- **Роутинг**: A* по сетке для лент, подземных лент, труб, подземных труб; расстановка столбов (покрытие + связность сети).
- Валидация: виртуальная проверка баланса (вход ≥ потребность).
- Расчистка: деревья/камни на пути → задачи `mine`.

**Готово, когда:** на тестовой карте бот раскладывает (пока «на бумаге» + рисунок PNG) шахту, плавильню и блок красной науки, соединённые лентами, без коллизий.

### Стадия 7. Ранняя игра (бутстрап)
Порядок (бот выводит сам из целей, но ожидаемый сценарий такой):
1. Руками: камень → печи; дерево/уголь; железо руками.
2. Burner-дрели на уголь (самоподпитка), железо, медь, камень.
3. Каменные печи под дрелями, сбор пластин.
4. Паровая электростанция у воды (помпа, бойлер, паровой двигатель), столбы.
5. Лаборатории + ручная красная наука → `automation`.
6. Электрические дрели, сборщики шестерней/красной науки, ленты.
7. Автоматическая красная наука → `logistics`, `electronics`, `steel-processing`, `logistic-science-pack`.

**Готово, когда:** автоматическая красная наука, исследовано всё по красной; бот сам заправляет burner-сущности, пока нет электричества на добыче.

### Стадия 8. Середина: зелёная, сталь, нефть, синяя
- Масштабирование плавильни (железо/медь/сталь) на main bus.
- Зелёная наука, green circuits. Военная наука для ракеты в base не нужна — пропускаем.
- Нефть: насосы на нефтяных полях, переработка, пластик, сера, red circuits, синяя наука.
- Расширение энергии (бойлеры → позже солнце/аккумуляторы).
- Модули/тех для эффективности по необходимости.

**Готово, когда:** стабильно идут красная+зелёная+синяя наука с заданной скоростью.

### Стадия 9. Строительные роботы
- Исследование `construction-robotics`, личный робопорт, модульная броня, солнечные панели/батареи для брони.
- Переключение layout-движка на выдачу чертежей: бот импортирует blueprint-строку через GUI и ставит призраки, следит за выполнением, подвозит материалы (логистика сундуками/логист. сеть).
- Логистические роботы для снабжения строительства.

**Готово, когда:** новый модуль ставится одной операцией «разместить чертёж + обеспечить материалы».

### Стадия 10. Финал: ракета
- Фиолетовая и жёлтая наука, LDS, ракетное топливо, процессоры.
- Исследование `rocket-silo`, постройка шахты, производство ракетных частей.
- Запуск ракеты → победа.

**Готово, когда:** ракета запущена, в логе ноль ручных действий.

### Стадия 11. Мониторинг и адаптация (сквозная, развивается с 5-й стадии)
- Истощение патчей: прогноз по оставшемуся количеству и скорости добычи → заранее новая шахта.
- Статусы машин: `no_input` → искать дефицит вверх по цепочке; `output_full` → затор; `no_power` → энергия.
- Энергия: удовлетворённость сети < 100% → расширение электростанции.
- Узкие места: сравнение фактической статистики с калькулятором.
- Топливо для burner-сущностей пока они есть.

### Стадия 12. Обобщение на другие карты
- Никаких захардкоженных координат: всё через сенсоры и поиск.
- Разведка: если нужного ресурса нет рядом — исследовать карту (ходить, чартить чанки).
- Тест-прогоны на 5–10 случайных сидах; метрики: время до каждой науки, время до ракеты, число перепланирований/ошибок.
- Дальше (вне текущего объёма): кусаки, оборона, Space Age.

## 3. Риски

| Риск | Что делаем |
|---|---|
| Промахи кликов / неверная проекция камеры | фиксированные разрешение/UI scale/зум, калибровка по `selected`, проверка каждого действия сенсорами |
| GUI меняется между состояниями (разные окна, поиск) | макросы с подтверждением шагов через `player.opened`, курсор, инвентарь; скриншоты для отладки |
| Скорость: ввод медленнее API | быстрые клавиши (Ctrl+клик, Q, quickbar); роботы как можно раньше |
| Ходьба застревает | A* по карте препятствий + детект застревания + расчистка |
| Большие дампы не лезут в RCON | пагинация или `helpers.write_file` в `script-output` сервера и чтение файла |
| Мод случайно меняет состояние игры | в remote interface только чтение; бот не шлёт произвольных `/c` |
| Раскладка лент — самое сложное | жёсткие шаблоны + простой A*, усложняем по необходимости |
| Бот «тупит» в цикле перепланирования | лимиты попыток, бан метода после N неудач, лог причин |
| Xephyr + OpenGL медленный | `-glamor`; fallback — отдельный X-экран или окно на основном дисплее (тогда мышь занята) |

## 4. Решённые вопросы

1. Клиент в Xephyr `:1` — ✅ работает.
2. `game.speed` — не меняем (1).
3. Сид — 12345.
4. Язык бота — Go.
